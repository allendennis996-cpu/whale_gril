# 自用与更新

本项目的源码、Release 和更新来源是 `https://github.com/allendennis996-cpu/whale_gril`。这是自己的 Fork，可以长期独立使用；自己的 `main` 与原作者的 `main` 分属两个仓库。提交、推送或一键更新均不会自动向原作者提出合并，也不会自动吸收上游改动。公开仓库中的源码可被其他人查看。

## 日常使用

已有项目环境无需重新安装。先启动 `启动鲸鱼娘.bat`，再启动 `启动微信桥接.bat`。源码首次安装需 Node.js 18+；接微信时在项目根目录执行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

桥接及守护脚本按 `.venv\Scripts\python.exe` → `runtime\python\python.exe` → 系统 Python 的顺序选择。主服务使用便携 Node 或系统 Node。不要删除已有 `.venv` 或 `runtime` 来尝试普通源码更新。

## 更新和保存自己的修改

双击 `一键更新.bat` 即可。保留 `.git` 的克隆目录从自己的仓库 `main` 快进，不依赖可能误配的 `origin`，也不执行自动合并、重置或自动暂存。未提交改动、其他分支、提交分叉时会停止；先保存自己的开发工作，再决定如何合并。`-Force` 不会覆盖这些源码修改。

```powershell
# 只检查，不改代码、配置、数据或 Git 引用
.\一键更新.bat -Check
.\一键更新.bat -DryRun

# 查看修改后，按实际文件名逐个添加，再保存到自己的仓库
git status
git diff
git add src/实际修改的文件.js
git diff --cached --name-only
git commit -m "说明这次修改"
git push origin main
```

一键更新负责下载已经推送的版本，不会代替提交或上传。本机已是远端最新提交时不会重复覆盖。Git 模式更新后手动重启主服务和桥接，避免进程继续使用旧代码。源码提交号比软件版本号更精确；只改源码不要求创建 Release。

无 `.git` 的解压目录继续使用自己的 Release 安装包；本仓库未发布相应 Release 时无法在线获取安装包。`Code → Download ZIP` 只有源码，推送源码不会自动产生便携运行环境。`一键装运行环境.bat` 只查询本仓库的 `v3.50/runtime-3.50.zip`，下载或解压失败保留原有环境。Release 缓存按仓库分开，避免误用原作者旧包。`-Zip`、`-Tag`、`-Rollback` 属于发行包操作，不等于 Git 快进。

## 本机数据和账号

以下内容只能留在本机，不提交 GitHub，也不带进源码包：

- `config.json`：主人 ID、白名单、备注与本机配置。
- `data/`：模型设置和密钥、聊天记忆、账号历史、身份目录及日志。
- 微信数据库、日志、截图和备份；`.venv/`、`runtime/` 属于本机环境。

身份目录按实际操作的微信账号隔离，包含已发现用户和群的 ID、名称、类型、最近出现时间，不含消息正文。即使对方不在白名单，也可登记身份元数据供下拉搜索。只有放行后才处理正文、媒体及自动回复。主人仅按真实发送者 ID 认证；有效主人 wxid 自动放行该用户私聊，所在群仍需单独加入群白名单，名称和备注没有权限。

账号固定选择优先；自动模式在桥接在线时选实际账号，桥接离线或服务重启时恢复最近操作过的账号及其名称。没有操作历史才参考已发现数据库的活跃时间。切换账号也会切换身份目录；无账号归属的旧数据不猜测合并。离线目录可搜索、可填备注，发送仍需在线桥接和已确认的微信窗口。

主人和白名单输入框支持按 ID 或名称搜索，也能手填。修改 ID 清空旧名称；自动识别不覆盖手写备注，“重新识别”后需点击“使用此名称”才替换已有名称。编辑草稿不改变权限，统一点击“保存修改”后生效；结果卡片只显示已保存配置。白名单检查读取最新落盘配置，撤销后停止后续处理和交付，旧历史保留。

## 常见问题

`127.0.0.1:8787` 报 `WinError 10061` 表示桥接连接不到本机主服务。先启动主服务，确认浏览器能打开 `http://127.0.0.1:8787/debug`，再检查桥接地址和端口。连接成功后若媒体识别仍失败，再在设置中测试视觉接口及转码环境。

“窗口还没认出来，现在不会发送”表示已有账号资料，但桥接尚未确认可操作的微信窗口；这与历史身份目录是否可用是两个状态。启动桥接并确认选择的账号已登录后再检查，不会因显示历史昵称而跳过窗口验证。

本项目测试使用临时目录、虚构 ID 和模拟发送器，不向真实联系人发送测试消息。开发验证参见 [维护手册](维护手册.md)。
