# 维护手册

本 Fork 主要供个人开发和使用。源码和更新来源固定为 `allendennis996-cpu/whale_gril`；日常提交到自己的 `main` 即可，不需要创建 PR 或回归原作者仓库。入门操作见 [自用与更新](自用与更新.md)。

## 目录与隐私

可以在同一个 Git 克隆目录开发和运行，不要求另设运行目录。若确实有第二份运行安装，用 `deploy.ps1 -Target <目标目录>` 同步；禁止把真实数据当作源码迁来迁去。

| 内容 | 处理方式 |
| --- | --- |
| `src/`、`web/`、`examples/`、`scripts/`、测试和文档 | 经过验证后提交自己的仓库 |
| `config.json` | 本机配置、主人与白名单，禁止上传或覆盖 |
| `data/` | Key、会话、账号资料及按账号隔离的身份目录，只留本机 |
| `.venv/`、`runtime/`、`node_modules/` | 本机环境，不同步、不放入源码包 |
| 微信数据库、日志、截图及 `backup/` | 本机资料，不上传 |

身份目录和操作账号历史需保留名称、ID、所属账号与时间，重启后可用；不把真实身份复制到测试、文档、源码或提交说明。测试只使用临时目录与虚构身份。无归属旧目录不可猜测合并。主人只认真实发送者 ID，名称和备注不得授予权限。

## 修改和验证

1. 查看 `git status`、`BUGS.md`、`CHANGELOG.md`，保留已有本地改动。
2. 定位问题并补充可复现的回归测试，测试不向真实联系人发送消息。
3. 执行相关检查，再执行完整测试：

```powershell
npm test
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py'
node scripts/release-check.js
```

`node scripts/release-check.js` 是开发目录检查。`--release` 仅用于不带配置和数据的干净源码树；直接在日常运行目录执行会因存在本机数据而拒绝。测试数量会随代码变化，不使用固定数量判断结果。

4. 修改用户可见行为时更新文档、`BUGS.md` 和版本记录。需要生成新软件版本时用 `npm run bump -- "改动说明"`，保持 `package.json` 与 CHANGELOG 最新数字版本一致；同一条补丁版本线保持连续。不需要为每次源码提交发布 Release。
5. 重启自己的主服务，确认页面、账号目录和配置保存正常。未运行的桥接不必为了测试而连接真实微信。
6. 按文件添加到暂存区，检查差异和文件名，确认没有身份目录、配置、密钥或运行数据，再提交推送。

```powershell
git status
git diff
git add src/实际修改的文件.js
git diff --cached --name-only
git diff --cached
git commit -m "说明改动"
git push origin main
```

## 源码更新与发行包

Git 目录双击 `一键更新.bat` 从自己的仓库 main 快进。`-Check` / `-DryRun` 不写入代码或 Git 引用；有未提交改动、其他分支或分叉时停止，不执行 reset、自动 stash 或覆盖，即使传入 `-Force` 也一样。更新不会提交或上传本地改动。Git 模式更新后手动重启服务和桥接。

无 Git 的解压目录从自己的 GitHub Release 下载安装包。发布源码与发布安装包是两件事，Fork 没有相应 Release 时需要继续使用源码目录。下载校验、备份与回滚仅描述发行包流程；Git 回退应按提交历史处理。Release 元数据、ZIP 和运行环境缓存按仓库分开，不借用原作者包。

仅当需要另一份安装或分享源码包时执行：

```powershell
# 同步代码，保留目标的配置、数据、Git 和环境；不重启
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\deploy.ps1 -Target D:\WhaleRun

# 显式要求重启目标项目的服务和桥接
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\deploy.ps1 -Target D:\WhaleRun -Restart

# 构建源码包；输出到自选目录，本机环境不入包
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build-release.ps1 -OutDir D:\WhaleRelease -SkipFull
```

部署逐个校验关键文件；失败不重启。更新/部署仅停止目标安装的进程，不全局结束 Node/Python。源码包不含 `.git`、`.venv`、`config.json` 和 `data/`；完整便携包须准备指定 `runtime`，二者均从 ZIP 复核源码哈希。本地出包脚本不上传 GitHub，也不创建 Release。

## 常见故障

| 现象 | 检查与处理 |
| --- | --- |
| 视觉接口连接 `127.0.0.1:8787` 被拒绝 | 先启动主服务，确认能打开 `/debug`，检查桥接地址和端口，再检查视觉服务 |
| 已有账号名但“窗口还没认出来” | 历史资料可用不代表窗口已确认；检查所选微信已登录和桥接状态 |
| 桥接提示缺依赖 | 启动脚本优先 `.venv`，在该 Python 安装 `requirements.txt`；其次检查便携环境 |
| 身份搜索不显示朋友 | 确认目录所属账号，账号间不合并；首次需桥接发现身份，旧历史离线仍可搜索 |
| 收到消息但不回复 | 先查用户/群白名单，再查群触发、禁言、冷却和窗口确认；主人有效 wxid 只自动放行私聊 |
| wxgf / HEVC 图片无法识别 | 检查 ffmpeg 与视觉模型配置；长截图和格式错误不是本机服务拒绝连接 |
| 更新显示未提交修改或分叉 | 先保留并处理自己的改动；不要用整包覆盖或强制重置来消除提示 |
| PowerShell 中文字符串解析失败 | `.ps1` 保存为 UTF-8 BOM，验证 Windows PowerShell 5.1 解析 |

`重置全部.bat` 会重建配置并移除运行数据，应仅在明确需要恢复出厂时使用；普通更新、重启或切换账号都不需要重置。
