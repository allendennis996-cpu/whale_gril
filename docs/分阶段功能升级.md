# 分阶段功能升级

以本项目为基线适配上游 68452df 的设计，不整体合并上游。

## 跨会话消息队列

调试台「功能开关」开启跨会话消息队列后，重启桥接生效。默认关闭，关闭后重启恢复原调度。同会话串行，跨会话最多四路并发，数据库访问和微信发送各自串行。OCR 兜底同样持有发送锁直至动作结束，卡死由原有看门狗终止桥接，不留下会在锁释放后继续发送的线程。

每会话待处理最多 64 条，总计 512 条；满载拒绝新消息并记录原因。相邻同一人的普通文本最多合并 8 条，命令、引用、@ 和媒体不合并。只在接纳时检查过期。队列不持久化，重启不重放。

切换账号或移出白名单取消待处理工作；真正发送仍按原目标确认流程执行，并复核回复人格版本。改人格后旧回复作废，游戏期间延迟的回复最长五分钟有效。禁止以昵称认证主人。

自动测试使用虚构账号；真实微信发送不作为无人值守验收的一部分。

## 联网语义判断

调试台功能开关中开启，默认关闭，保存即时生效。只在允许回复的消息中判断检索意图；使用当前聊天模型，单次输出最多 160 token、两秒总超时、无自动重试，支持的模型仅本次关闭思考，不改变主回复设置。

关闭时沿用原规则；超时、异常或非法 JSON 回退关键词规则。明确搜索、天气有规则兜底，明确 B站或微博限定站点。严格时效检索不把全部过期结果重新当作有效结果。搜索失败继续聊天，不伪造检索资料。


## 记忆 v2：维护式启用

当前默认继续使用旧 Store。记忆 v2 不提供热切换开关，必须先停止主服务和桥接，暂停网页聊天，再在项目目录执行维护命令。迁移不会修改或删除原始 `data/store.json`，也不会根据当前选中微信账号猜测历史归属。

先做只读预检（不要求停服务；数字以读取时刻为准）：

```powershell
node scripts/memory-v2.js inspect
```

预检输出会话数、消息数、损坏会话数 `damaged` 和账号缺失会话数 `unassigned`。有损坏记录时迁移拒绝切换，先处理原文件；微信无归属记录保存在待认领区，不进入任何账号上下文。只有记录内来源账号证据或本机明确提供的映射可以确定归属。映射文件的键使用旧会话键，值为实际来源账号，下面全部是虚构示例：

```json
{"wechat:u:demo-peer":"demo-account-a"}
```

映射文件包含本机身份信息，应保存在本机隐私目录，不能提交。停止主服务和桥接后执行：

```powershell
node scripts/memory-v2.js migrate
# 有经过本机确认的归属时改用：
node scripts/memory-v2.js migrate --accounts "本机映射.json"
```

维护工具核对进程锁、桥接 PID 和主服务端口，建立包含当前记忆、独立人格文件、绑定、设置及本机密钥的保底快照，然后向新的独立目录写入，校验消息数量与内容哈希，最后原子切换 `data/memory-mode.json`。保底快照在 `data/backups/memory-maintenance-*/`，不会被日常自动备份清理。这些快照含隐私和密钥，只能保留本机。

迁移可重复执行，不重复导入。已经使用 v2 时，可再次提供映射认领待归属记录；若会与当前同账号会话冲突，工具拒绝自动混合。中断未切换的临时目录保留，重试以活动模式文件为准。完成后重启主服务与桥接，调试台应显示存储模式 v2。

### 共享范围与持久化

微信内部以「平台、实际来源账号、私聊/群聊、会话 ID」共同隔离，网页仍使用原会话 ID。同一会话切换人格后可使用旧聊天、笔记及摘要；人格设定仍独立，旧人格回复只作为历史资料，当前身份由当前人格决定。人格变更依旧使生成中或延迟发送的旧回复失效。

消息使用追加日志，确认前执行磁盘同步。人物资料和摘要使用原子元数据文件；检查点与日志序号恢复未落入元数据的追加。未完成的尾行保留为损坏尾部副本后修复，中段损坏拒绝启动，不清空会话。清空记忆追加重置事件，旧后台任务不能恢复被清空的记忆。首版不自动淘汰消息原文，清空前的物理日志也保留本机。

### 预算、整理与检索

沿用私聊、群聊历史条数上限，增加 `memory.dialogueBudget`，默认 5500 token。先保留最近对话，再用余量加入摘要和本地文本检索，最多返回五条。调试台显示系统、历史、摘要、检索和输出预留的估算用量。token 为保守估算，不能替代服务商 tokenizer。

`memory.contextTokens` 为模型完整上下文上限，默认 0：已核实的官方模型使用已知能力，未知模型显示未指定，可按服务商文档填写。输出预留沿用当前模型的独立输出预算。超出已配置上下文的请求会被拦截，不把上游的 64000 当作统一容量。

累计二十条新用户消息或近期历史超过预算时，异步整理；全局仅一个任务，同会话至少间隔五分钟。使用当前聊天模型，每次最多输出 1000 token，三十秒超时，无自动重试；仅本次辅助调用关闭模型支持的思考选项。聊天不等待整理，失败保留原文和旧摘要。切号、撤权、重置、恢复与关闭服务会阻止旧结果写回。新增诊断只记录状态与通用失败原因，不记录正文。未增加嵌入 API 或向量数据库。

### 备份、恢复与回退

备份格式升级为 v2，仍支持 v1 导入；覆盖独立人格正文、绑定、设置和记忆。导出默认脱敏，恢复时本机已有密钥优先。v2 恢复必须停止主服务与桥接后执行，不能从正在聊天的服务里在线切换：

```powershell
node scripts/memory-v2.js restore --bundle "备份文件.json"
```

v1 备份中的未知微信归属继续待认领。恢复前同样建立不自动清理的保底快照。

回退先停止主服务、桥接和所有聊天写入，再执行：

```powershell
node scripts/memory-v2.js rollback
```

工具把当前账号隔离的全部消息、笔记和状态投影到 `data/store-isolated.json`，切换到本版本的兼容旧算法；保留全部 v2 日志和派生数据。重启后调试台显示 `legacy-isolated`。需要再启用时重新执行离线迁移。不能直接换回不认识新账号命名空间的历史代码。队列回退为关闭开关并重启桥接；联网路由回退为关闭开关。

## 验收与启用顺序

代码按消息队列、语义路由、记忆 v2 分阶段提交。实际配置仍保持两项开关关闭、旧存储模式，不主动迁移真实数据。先启用并验收队列，再启用联网判断，最后安排记忆维护窗口。每阶段发现异常先执行相应回退，不自动进入下一阶段。

基线：Node 562 通过、5 跳过，无失败；Python 79 通过。新增测试覆盖事件控制的并发与顺序、权限撤销、来源去重、人格失效、辅助 HTTP 超时断连、迁移幂等、未知账号、半写尾部、进程直接退出、原子切换前中断、重置与后台结果竞争、回退、备份密钥保护。

浏览器验收使用虚构独立数据，覆盖网页聊天、人格导入取消与确认、草稿待保存、会话绑定、新开关保存、预算展示、备份导出、维护恢复及移动页面。真实微信发送与付费模型服务未执行自动测试，启用后只在用户明确授权的目标完成现场验收。测试报告、截图与发布检查产物均在项目外，源码包不含本机数据。
